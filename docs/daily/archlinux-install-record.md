# Arch Linux 安装记录

记录一次使用官方提供的 `archinstall` 脚本安装 Arch Linux 的经历及遇到的问题。

## 中文显示乱码

在运行 `archinstall` 时，如果将其语言设置为中文，终端中可能会出现乱码，影响菜单和选项的正常阅读。

当前更稳妥的方式是：

- 安装过程中继续使用英文界面；
- 配置好系统和桌面环境后，再根据需要设置中文语言、输入法和字体。

## 用户与 Root 用户

`archinstall` 在创建普通用户时，可以同时保留 Root 账户并锁定 Root 登录密码，或将普通用户加入 `wheel` 用户组以便使用 `sudo`。

这通常比直接登录或长期使用 Root 更推荐：

- 日常操作使用普通用户，降低误操作导致系统损坏的风险；
- 需要执行系统管理命令时，再使用 `sudo`；
- Root 账户保留为应急账户，登录密码可在需要时通过相应方式设置。

不过，普通用户是否加入 `wheel` 用户组，以及是否允许通过 `sudo` 获得 Root 权限，都应根据实际使用场景配置。更安全的实践是按最小权限原则授予权限，避免无必要的免密 `sudo`。

## 磁盘分区

首次安装时选择了 `archinstall` 的自动分区，未成功完成自定义分区配置。自动分区能够快速得到可正常启动的系统，适合第一次安装或不需要复杂布局的环境。

后续可以尝试：

- 手动划分 EFI、Root、Swap 和可选的其他分区；
- 使用 Btrfs 或 LVM 等布局；
- 分区前确认磁盘设备名称及数据是否需要备份。

自定义分区存在数据误删风险，操作前应完整确认目标硬盘。

## 内核选择

安装时选择了多个内核：

- **linux-lts**：稳定性较高，适合追求稳定和兼容性的系统；
- **linux-zen**：面向桌面和交互体验优化，适合日常使用。

保留多个内核后，即使某个内核出现问题，也可以在启动菜单中选择其他内核。需要注意的是，多内核可能占用更多磁盘空间，并且需要处理相关的硬件或模块兼容性问题。

## 桌面环境

选择 KDE Plasma 桌面环境时，建议选择：

- `kde-plasma` 这类较精简的桌面组件；
- 不优先选择 `kde-meta` 或带有 `meta` 后缀的捆绑包。

带有 `meta` 后缀的包通常会通过依赖关系一次性拉入大量软件。即使只需要其中部分程序，也可能需要整组安装或卸载，软件选择和维护的控制粒度较差。

## 软件包选择

首次安装时没有额外勾选常用软件，完成后发现缺少 `konsole` 等日常工具，使用起来不太方便。自定义软件时，至少可以考虑：

- `dolphin`：文件管理器；
- `konsole`：终端模拟器；
- KDE 基础桌面组件和必要的系统工具；
- 仅根据个人需求安装浏览器、编辑器、媒体播放器等软件。

一般不建议仅为了使用少量组件而选择带 `meta` 后缀的 KDE 软件包组。逐项选择更容易控制系统规模，也可以避免一次性安装大量不使用的软件。
